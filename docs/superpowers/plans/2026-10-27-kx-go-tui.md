# kx (Go rewrite + TUI) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the bash `kxconfig`/`kxswap` with one Go binary `kx`: symlink-based project switching, safe merges, backups, an isolated `kx shell`, and a Bubble Tea TUI.

**Architecture:** UI-agnostic core packages (`fsutil`, `kubecfg`, `backup`, `store`, `shell`) hold all logic and are fully unit-tested against temp dirs. `cli` (cobra) and `tui` (Bubble Tea) are thin layers over `store`. Release via GoReleaser driven by release-please.

**Tech Stack:** (owner asked for the latest versions of everything) Go **1.27** (`go 1.27.0` + `toolchain go1.27.3` in go.mod), `k8s.io/client-go v0.37.1` (`tools/clientcmd`, `tools/clientcmd/api`), `github.com/spf13/cobra v1.10.2`, Charm v2: `charm.land/bubbletea/v2 v2.1.0`, `charm.land/bubbles/v2 v2.2.1`, `charm.land/lipgloss/v2 v2.0.6`, `github.com/charmbracelet/x/exp/teatest/v2` (tests only), `golang.org/x/term`. Bubble Tea v2's API differs from v1 (key messages, `View`, program options) — read the v2 source/docs in the module cache, never v1 examples. golangci-lint v2.15.0, GoReleaser v2.19.x.

**Spec:** `docs/superpowers/specs/2026-10-27-kx-go-tui-design.md` — read it before any task; this plan does not repeat its rationale.

## Global Constraints

- Module path `github.com/nunoarmada/kxconfig`; binary `kx`, entry `cmd/kx/main.go`.
- Every file kx writes containing kubeconfig data is mode `0600`; every directory kx creates under `kx/` is `0700`.
- Root dir = `$KX_HOME` if set, else `~/.kube`. Every path derives from it; tests always set a temp root.
- Project name regex `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`; discovery ignores names ending `.lock`, `.bak`, `.orig`, `.swp`, `~`.
- Backups: `<root>/kx/backups/<project>/<id>.yaml`, keep newest **20** per project. Initial adoption backups go to project `_initial`.
- Switching projects never changes namespaces. ctx/ns switches do not create backups (non-destructive; my call); every other mutating op backs up first.
- Never print or render secret values (tokens, keys, cert data, passwords).
- Non-interactive commands never prompt when stdin is not a TTY: fail with a message naming `--yes`.
- Always use the latest stable release of every dependency, tool and GitHub Action at the time of writing.
- Code, comments, docs in English. `gofmt`, `go vet`, `golangci-lint run` clean.
- Commits: conventional commits; the final release task commit carries `BREAKING CHANGE:` so release-please bumps to 2.0.0.

## Review Focus

1. Existing users' `~/.kube/config` is a regular file matching no project → first `kx use` must never lose it (backup + explicit choice). Test in Task 5.
2. Imported kubeconfig with relative cert/key paths (minikube style) → paths resolved relative to the *source file*, then inlined; re-importing the same file is a no-op. Test in Task 2.
3. `kx` (TUI) started without a TTY (piped/CI) → clear error, exit 1, no panic. Test in Task 7.
4. Terminal smaller than 80×24 or resized mid-session → single-pane fallback, no panic, no index out of range. Test in Task 8.
5. Kubeconfig with zero contexts, or `current-context` naming a missing context → lists/details render, `ns` returns a clear error. Test in Task 3 and Task 8.
